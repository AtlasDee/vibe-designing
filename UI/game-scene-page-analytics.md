# Game 场景：已装修页面运营总览

## 1. 适用范围

本参考用于“运营后台 → Home → Game 场景 → 已装修页面/标签”的查看态页面。用户选择自己配置过的对象后，手机展示对应页面结构，右侧展示该页面的整体运营指标和组件列表。

当前分析基线（2026-10-05）：

- 产品原型：`〔产品原型地址〕`
- 原型目标：`运营后台-首页-game页面-slot-h5`
- 线上入口：`〔UAT 后台地址〕`
- Figma 文件：`一站式运营后台--Copy-`
- Figma 节点：`30232:329938`
- UI 视觉基线：`UI设计图-频道场景`

本轮只定义页面级运营总览与组件入口。单个组件被点击后的组件数据和策略详情在后续组件规范中继续补充。

## 2. 页面在业务中的位置

页面层级：

`运营后台 → Home → Game 场景 → 已装修页面/标签 → 页面组件`

各层职责：

| 层级 | 对象 | 主要作用 |
| --- | --- | --- |
| 运营后台 | 后台业务域 | 提供统一导航和运营工作台 |
| Home | 场景入口 | 选择 Game、频道页等运营场景 |
| Game 场景 | 页面容器 | 承载运营配置好的 Game 页面 |
| 页面/标签 | 当前查看对象 | 决定手机布局、组件集合和页面指标 |
| 组件 | Banner、Local Favorites 等模块 | 提供组件级数据和策略下钻入口 |

核心闭环：

1. 用户进入 Game 场景。
2. 用户选择一个已配置对象，例如 `slot-demo演示`。
3. 手机加载该对象对应的 Banner、Local Favorites 等模块及其排序。
4. AI 助手 确认当前页面，并展示页面数据总览和组件列表。
5. 用户点击手机模块或组件列表行，进入该组件的运营上下文。

## 3. Game 场景与频道场景的关系

产品原型源码明确将 Game 场景定义为频道场景的同构场景，并复用：

- 页面选项卡。
- 页面数据总览。
- 组件列表。
- 手机预览。
- 组件下钻。
- 策略入口。

因此，`UI设计图-频道场景`可以作为 Game 场景的布局和组件基线。设计时只替换场景身份、当前页面、手机内容和数据，不重新发明另一套卡片体系。

同时要注意：原型为了脱离后端独立演示，将 Game 与频道场景的数据做了深拷贝。原型注释同时说明，这只是造数方式，不是产品的数据模型。正式设计和实现应依据产品路由关系决定是否共享同一页面配置，不能因为原型有两份数据，就设计成需要运营重复维护两次。

## 4. 对象名称必须先归一

原型中存在两个容易混淆的选择对象：

1. 手机上方的页面 Tab：选择已装修页面，例如 `Slot-h5`、`Slot-iOS`。
2. 手机标题区的标签选择：选择预览人群标签，用于查看不同人群下的页面内容。

线上示例中的 `slot-demo演示`可能是页面显示名、页面标签，或预览人群标签。仅凭显示文案不能判断对象类型。

分析新页面时至少记录：

| 字段 | 说明 |
| --- | --- |
| `sceneId` | Game 场景身份 |
| `pageId` | 已装修页面身份 |
| `pageName` | AI 助手 和面包屑使用的页面名 |
| `tagId` | 预览标签或人群标签身份 |
| `tagName` | 手机中展示的标签名 |
| `componentIds` | 当前页面包含的组件及顺序 |

如果产品将页面和标签合并为一个选择器，也要在数据层保留真实对象关系。切换后必须以同一次状态更新完成手机内容、右侧数据和导航，避免短暂展示不同对象的数据。

## 5. 页面整体布局

沿用运营后台首页的生产壳层：顶部一级导航、左侧运营导航、中间手机预览、右侧 AI 助手 工作区。桌面基线继续使用 `1920 × 1080px`，顶栏、侧栏和左右分区不因进入 Game 场景而改变。

### 5.1 中间预览区

- 页面选择控件位于手机上方，并与手机列居中对齐。
- 手机保持 `375 × 812px` 设计基线，不因右侧内容增多而缩窄。
- 当前页面或标签名称应在选择控件中清晰可见。
- 手机模块顺序来自页面配置，不按模块类型在前端重新排序。
- 模块必须保留稳定点击热区；悬停和选中反馈不能改变模块尺寸。
- 切换页面/标签时清除旧组件选中态，手机滚动位置回到产品定义的位置，默认回顶部。

### 5.2 右侧工作区

固定顺序：

1. 面包屑。
2. AI 助手 当前页面问候。
3. 页面数据总览。
4. 组件列表与筛选卡。
5. 后续组件子对话或策略能力。
6. 查看态底部固定 AI 输入栏；进入策略编辑等覆盖层后由覆盖层接管。

面包屑建议：

- 页面态：`运营后台 > 首页 > Game页面 > slot-demo演示`
- 组件态：`运营后台 > 首页 > Game页面 > slot-demo演示 > Banner`

原型中的层级顺序为 `首页 > 场景 > 页面 > 组件`。界面文案可按产品命名使用 Home/首页，但同一产品内必须统一。

## 6. AI 助手 页面问候

页面已被选择后，不再展示通用的“请选择运营场景”，而是确认当前对象。

推荐模板：

`{时段问候}，尊敬的 {account} 指挥官！我来为你介绍 {pageName} 页面的具体运营情况`

示例：

`下午好，尊敬的 claire@ 指挥官！我来为你介绍 slot-demo 页面的具体运营情况`

规则：

- `{时段问候}`动态生成，不固定写“下午好”。
- `{account}`来自登录账号，不把示例账号写进设计常量。
- `{pageName}`取当前对象的正式显示名，不从手机模块标题推断。
- 切换页面后更新现有页面上下文，不重复堆叠多条相同结构的欢迎信息。
- 问候、页面卡片和手机内容必须使用同一次选择结果。

## 7. 页面数据总览

总览包含三个页面级指标：

| 指标 | 主值 | 辅助信息 |
| --- | --- | --- |
| PV | 当前统计周期页面浏览量 | 七日均值、较 T-7 变化 |
| UV | 当前统计周期独立访问用户 | 七日均值、较 T-7 变化 |
| 停留时长 | 当前周期平均停留时长 | 七日均值、较 T-7 变化 |

原型默认统计时间为最近 7 天，并明确时区 `〔业务所在时区〕`。正式页面应由数据接口返回统计区间和时区，不用设计稿中的日期作为固定文案。

展示规则：

- 主值是视觉重点。
- 七日均值作为次级说明。
- T-7 变化显示方向和数值；上涨、下降和持平不能只依赖颜色。
- 缺失数据使用统一空值符号，不把 `0` 与“无数据”混为一谈。
- 三项指标属于页面级数据，不受组件列表筛选影响。

原型的紧凑规格可作为相对比例参考：指标名称约 `12px`，主值约 `22px`，辅助信息和变化值约 `12px`；正式设计应绑定组件规范中的文字变量。

## 8. 组件列表

组件列表由“统计筛选卡 + 组件明细”组成。四张统计卡按一行排列：

1. `组件总数`
2. `已配置策略组件`
3. `未配置策略组件`
4. `运营策略数`

产品原型中第四项命名为“运行策略数”，本次业务口径使用“运营策略数”。后续应由产品统一术语，不在同一页面同时出现两种名称。

### 8.1 统计卡也是筛选器

- 默认选中“组件总数”，展示全部组件。
- 点击“已配置策略组件”只展示已配置组件。
- 点击“未配置策略组件”只展示未配置组件。
- 点击“运营策略数”时，展示包含运行中策略的组件；不能仅因为组件处于已配置状态就默认一定有运行策略。
- 再次点击当前非“全部”筛选，可回到全部；也可以按最终组件规范提供明确的“全部”行为。
- 筛选变化时列表回到收起态，并重算当前结果数量。

视觉层级：

- 普通计数卡使用中性底色。
- 未配置数量大于 `0` 时使用警示色，但不使用错误态红色。
- 运营策略数使用品牌强调色。
- 悬停和选中需要边框、底色或聚焦环，不只改变数字颜色。

### 8.2 组件明细

每条组件明细至少展示：

- 组件名称。
- 组件 ID。
- 策略数量，或“未配置”。
- 已配置组件的 `PV`、`UV`、点击量、`CTR(PV)`、`CTR(UV)`、流量占比。
- 未配置组件显示“未配置策略，暂无数据”，不伪造零值。

整条组件明细可点击。手机中的同一模块和明细行必须进入同一个组件 ID，不能按显示名称模糊匹配。

### 8.3 三条折叠规则

- 筛选结果 `≤ 3` 条时全部正常展示，不出现展开控件。
- 筛选结果 `> 3` 条时默认展示前 `3` 条，其余收起。
- 展开入口显示总数，例如“展开全部 6 个组件”。
- 展开后入口变为“收起”，收起后回到前三条。
- 排序在折叠前完成，默认遵循手机中的组件顺序。
- 切换页面/标签或筛选条件后恢复默认收起态。

这条规则控制的是组件明细数量。页面级“策略组/策略列表”在产品原型中是另一块能力，原型默认展示前 `5` 项，不能与这里的三条组件规则混用。

## 9. 点击组件后的联动

本轮只规定入口行为：

1. 手机模块或右侧组件明细进入选中态。
2. 面包屑下钻到组件层级。
3. 右侧追加或切换为该组件的数据和策略上下文。
4. 页面数据总览仍属于父页面，不被误改为组件数据。
5. 返回页面层级时清除组件选中态，保留当前页面/标签选择。

原型中的组件进入子对话后会展示组件数据概览、策略组和策略列表。具体字段、编辑入口和卡片形式等待组件专项规范，不在本页面先行写死。

从组件点击“新建策略”后进入的上下文抽屉，读取 [strategy-editor-drawer.md](strategy-editor-drawer.md)。

## 10. 原型、设计与线上的转化关系

### 产品原型提供

- Game 与频道场景同构的业务模型。
- 已启用页面的 Tab 和页面列表入口。
- 页面指标及最近 7 天比较方式。
- 四张组件统计卡兼作筛选器。
- 组件明细整行点击和前三条折叠。
- 面包屑从场景、页面下钻到组件。
- 额外的页面级策略列表、策略中心和页面装修入口。

### UI 设计需要完成

- 将频道场景的成熟视觉规范复用到 Game 场景。
- 保持手机在中间列居中，右侧数据卡与消息列对齐。
- 把原型中的高密度信息整理为页面指标、统计筛选卡和组件明细三个层次。
- 明确筛选卡的默认、悬停、选中和警示状态。
- 让三条折叠在视觉上显得是列表控制，不是新的数据卡。
- 处理长页面名、长组件名、较多页面 Tab 和窄屏溢出。

### 线上实现验证

- 当前账号、问候时段和页面名为动态数据。
- 页面选择会实时改变手机模块和右侧数据。
- `slot-demo演示`、Banner、Local Favorites 等只是当前配置示例。
- 查看态底部 AI 输入栏持续显示“AI 功能开发中，敬请期待”并配发送按钮。

### 不应直接继承的原型细节

- 原型的 Game/频道数据深拷贝不是正式数据结构。
- 原型问候固定写“早上好”，正式页面必须动态生成。
- 原型第四张卡叫“运行策略数”，需与当前产品术语统一。
- 原型中的页面级策略列表默认五条，不能套用组件列表的三条规则。

## 11. 数据与状态契约

页面总览至少需要：

```text
sceneId
pageId
pageName
tagId / tagName（如适用）
lineage（如产品需要展示）
statRange
timezone
metrics.pv: current / sevenDayAverage / deltaT7
metrics.uv: current / sevenDayAverage / deltaT7
metrics.stay: current / sevenDayAverage / deltaT7
componentSummary: total / configured / unconfigured / runningStrategies
components[]: id / name / configured / strategyCount / metrics / order
```

必须覆盖：

- 页面加载中。
- 页面不存在或已下线。
- 页面暂无组件。
- 页面有组件但全部未配置。
- 指标无数据。
- 数据接口部分失败。
- 无查看权限。
- 页面/标签切换中。
- 组件数量小于等于三和大于三。
- 筛选结果为空。

## 12. 验收清单

- 进入 Game 场景后，生产壳层和三栏比例不跳变。
- 页面/标签选择器与手机在同一预览列中居中。
- 选择 `slot-demo演示` 后，问候、面包屑、手机模块和右侧数据均指向同一对象。
- Banner、Local Favorites 等模块顺序来自当前配置。
- 页面数据总览只包含 PV、UV、停留时长及其对比信息。
- 四张组件统计卡的数量与实际组件数据一致，并能筛选列表。
- 未配置组件不展示伪造指标。
- 组件结果超过三条时只展示前三条，并可展开和收起。
- 点击手机模块与点击同名组件行进入同一个组件 ID。
- 组件态的面包屑、手机选中态和右侧内容同步。
- 未打开策略编辑等覆盖层时，消息区滚动过程中面包屑和底部 AI 输入栏保持可见。
- 页面 Tab、页面标签和人群标签没有因文案相似而被错误合并。
