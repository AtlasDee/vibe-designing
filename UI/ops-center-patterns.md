# 运营后台设计规范

这是从现有运营后台页面提炼的设计基线。产品需求没有明确指定时，以此为默认。

## 视觉基线

| 项目 | 默认规则 |
| --- | --- |
| 界面性格 | 安静、理性、高信息密度，服务于长时间查询、对比和配置 |
| 主色 | `#5472C6` 附近的品牌蓝，用于主按钮、选中态和重点链接 |
| 顶部区 | 深蓝 `#234786` 附近，白色文字；桌面端高度约 82px，随宽度递减至约 50px |
| 页面背景 | 非纯白的弱冷色渐变，从 `#F4F0FD` 过渡到 `#E2EDFA` / `#E7F1FE`；内容区保持克制 |
| 字体 | Inter，中文回退 PingFang SC/系统无衬线体 |
| 字号 | 页面标题 20–24，区块标题 16–18，正文/表格 14，辅助信息 12 |
| 字重 | 页面标题 600，表单标签 500，正文 400 |
| 圆角 | 输入框、按钮、弹窗和单层卡片使用 4–8px；不使用胶囊式容器 |
| 间距 | 以 8px 为基础：8/16/24/32；表单项水平间隔约 32px |
| 控件高度 | 常规输入框、选择器、按钮 32px；保持查询区紧凑 |

若现有 Figma 文件已有设计变量，以库变量为准，不新建一组近似色值。

## 页面骨架

```text
顶部应用栏 / 主导航
└─ 内容容器
   ├─ 页面标题、面包屑或标签导航
   ├─ 查询区（内联表单，可换行）
   ├─ 操作区（主操作左侧，工具类操作右侧）
   ├─ 数据表格 / 树表
   └─ 分页与总数
```

- 页面内容优先满宽排布，只为可读性设定合理最大宽度。
- 查询区与表格是同一工作流，不用多层卡片分割。
- 查询项的常规宽度约 220px；日期区间、系统选择和多选可更宽。
- 窄屏时查询项自然换行，按钮保持固定尺寸，不随文字或加载态跳动。

## 查询区

- 常用组件：关键字输入、单选/多选选择器、级联选择、日期时间区间、状态选择。
- 操作顺序：`Search` 为主按钮，`Reset` 或 `Refresh` 为次按钮或图标按钮。
- 仅有单一精确条件且无默认列表意义的页面，可在条件为空时禁用查询。
- 低频条件进入“更多筛选”折叠区，展开不应改变表格列宽。
- 查询过程保留当前条件；返回 0 条时显示空结果，不清空用户的筛选。

## 操作区

- 常规顺序：`Add` → 批量操作 → `Export` → 列显隐/刷新。
- 页面只能有一个视觉主按钮，通常是新增或提交。
- 刷新、列显隐等熟悉工具使用图标按钮并提供 tooltip。
- 导出必须明确范围：当前结果、勾选记录或全部数据。大数据量时显示生成中状态。
- 无权限的操作默认隐藏；若必须展示以便解释流程，则禁用并说明原因。

## 表格与树表

- 表头和内容默认中对齐；长文本、名称和描述左对齐，数字可右对齐。
- 大尺寸行内垂直留白约 12px，单元格水平留白约 16px。
- 首列可用勾选框或主标识固定在左侧，`Action` 列固定在右侧。
- 单元格超长时省略并用 tooltip 显示全文；不为单个长字段无限拉宽整表。
- 常规行操作为查看、编辑、删除、权限配置、绑定/解绑、启用/停用。两项以上时可收入“更多”菜单，但最常用的一项要保持直接可见。
- 审计字段通常放在表格后部：创建人、创建时间、更新人、更新时间。
- 表格需要加载骨架、空态、错误重试、局部刷新和分页。刷新不应使整页闪白。

## 表单与弹窗

- 普通新增/编辑弹窗宽度默认约 400px；长表单使用 600px；菜单、权限树或双栏配置使用 800–1000px。
- 需要持续对照手机预览、同时编辑多份策略的长流程，不使用普通居中弹窗；改用顶部导航下方的上下文侧边工作区，并保留触发对象可见。策略场景读取 [strategy-editor-drawer.md](strategy-editor-drawer.md)。
- 标题使用“新增/编辑 + 对象名”，底部右对齐 `Cancel` 和主操作 `Confirm/Save`。
- 字段按“基本信息 → 归属/权限 → 状态 → 扩展信息”排布。长表单分组，不使用一条贯穿到底的表单。
- 必填、长度、格式、唯一性和字段依赖要有明确验证。错误提示放在字段下方，不只用 toast。
- 编辑时载入现有数据；提交期间禁用重复提交，但不改变弹窗尺寸。
- 关闭已修改但未保存的表单时，提示丢弃变更。

## 反馈与状态

| 状态 | 表达 |
| --- | --- |
| 成功 | 轻量成功提示，更新当前表格并保留筛选 |
| 错误 | 说明错误原因和可执行的下一步；表单错误定位到字段 |
| 加载 | 表格内局部 loading/骨架，主按钮显示处理中且宽度稳定 |
| 空态 | 区分“暂无数据”和“无匹配结果”；有新增权限时可提供主操作 |
| 禁用 | 视觉弱化并通过 tooltip 或辅助文字说明原因 |
| 危险操作 | 确认弹窗明确对象、影响和不可逆性；危险按钮使用红色 |

## 权限与审计

- 在页面级别控制访问，在组件级别控制新增、编辑、删除、导出、权限配置等操作。
- 现有常见角色为 `SUPER_ADMIN`、`BS_ADMIN`、`AUDIT_ADMIN`、`NORMAL_USER`。不假定所有角色拥有同等操作权。
- 详细审计内容可包含：系统/业务线、操作人、IP、操作类型、请求参数、响应、操作时间、耗时。
- 参数与响应中的敏感数据必须脱敏；长 JSON 使用详情弹窗、代码块或折叠展示。

## 响应式与可用性检查

- 桌面端优先，建议以 1440px 宽度设计主稿，同时检查 1280px 及更宽屏幕。
- 窄屏不压缩表格到无法读取；使用横向滚动、固定关键列和列显隐。
- 键盘焦点可见，弹窗打开后焦点进入弹窗，关闭后回到触发元素。
- 表单标签与输入控件关联，图标按钮有可读名称，状态不只依赖色彩。
- 最终检查文字溢出、弹窗遮挡、滚动容器冲突、分页跳动和加载时布局变化。
