# 策略编辑工作区：新建策略

## 1. 适用范围

本参考用于运营人员已经选中一个页面组件，并点击“新建策略”“复制策略”或“编辑策略”后的配置工作区。该模式服务于较长、可下钻、可能同时维护多份策略的任务，不是普通确认弹窗。

当前设计基线（2026-10-15）：

- Figma 文件：`一站式运营后台--Copy-`
- 画板：`新建策略`，节点 `30227:317004`
- 原型截图：`新建策略弹窗-原型图`，节点 `30284:324807`
- UI 设计：`新建策略弹窗-设计图`，节点 `30284:324854`
- 策略工作区实例：`装修管理`，节点 `30284:324921`
- 复用组件：`Property 1=策略配置`，组件 key `3007fa6c812fb39841634a1f938d1246638629b5`

设计文件中沿用“弹窗”命名，但从尺寸、停靠和交互看，它应作为大型上下文抽屉处理。

## 2. 业务入口与上下文

进入条件：

1. 用户位于 Game 或频道场景的某个已装修页面。
2. 用户在手机或组件数据区选中具体组件。
3. 用户点击该组件的“新建策略”。
4. 策略工作区覆盖右侧内容，但保留左侧手机与当前组件高亮。

进入工作区时至少携带：

```text
sceneId
pageId
componentId
componentName
strategyDrafts[]
activeStrategyId
```

策略的 `Where` 必须来自触发入口的 `componentId`，不能只靠组件名称匹配。

## 3. 工作区不是普通弹窗

1920 × 1080 设计基线：

| 区域 | 位置或尺寸 |
| --- | --- |
| 全局顶部导航 | `y = 0`，`h = 82px`，始终保留 |
| 策略工作区实例 | `x ≈ 0`，`y = 82px`，`1920 × 998px` |
| 左侧上下文保留区 | `x = 0`，`w = 629px` |
| 右侧策略抽屉 | `x = 629px`，`w = 1291px`，`h = 998px` |
| 抽屉内容内边距 | 左右约 `40px` |
| 抽屉主体背景 | 白色，使用既有 `弹框bj` 实例 |
| 抽屉分隔阴影 | 蓝色阴影，约 `60px` 模糊、`25%` 不透明度、`y = 4px` |

用户所说的“从左边拉出”在设计稿中的实际结果是：抽屉左边界向手机方向推进，抽屉主体仍停靠在右侧。实现动画时应从右向左滑入，最终停在 `x = 629px`；不要从浏览器最左侧覆盖进来。

左侧保留区包含：

- `100px` 运营后台侧栏。
- 约 `529px` 手机预览列。
- `375px` 手机主体及当前组件高亮。

设计稿的遮罩层视觉不透明度为 `0`。这表示设计师取消了原型中的灰色蒙层，让手机保持清晰可见；但背景业务控件默认应被点击隔离，避免编辑策略时意外切换页面或组件。若产品要求手机继续可滚动或可预览，必须明确允许的操作范围。

## 4. 原页面在编辑态的变化

- 顶部一级导航保持可见，用户仍知道自己位于运营后台。
- 左侧导航和手机保持原位置，不因抽屉出现而重排。
- 右侧 AI 助手 消息区和底部 AI 输入栏被抽屉覆盖。
- 不在策略抽屉内部重复展示面包屑、AI 助手 或 AI 输入栏。
- 当前组件继续在手机中高亮，建立“手机对象 → 策略表单”的空间联系。

设计稿中的 Banner 高亮框约 `392 × 154px`，使用品牌蓝 `#1577FF`：

- `3px` 描边，约 `60%` 不透明度。
- 向下蓝色阴影，主阴影约 `16px` 模糊、`2px` 扩展、`y = 8px`。
- 高亮不得改变手机模块原来的布局尺寸。

## 5. 顶部结构

抽屉顶部由两行组成，整体位于抽屉内 `x = 40px`、`y = 30px`，宽 `1211px`。

### 5.1 标题行

- 标题行高度 `30px`。
- 返回按钮 `24 × 24px`，位于标题左侧。
- 标题使用 `{componentName} 策略`，设计稿示例为 `Banner 策略`。
- 标题字号 `20px`，颜色约 `#111827`。
- 关闭按钮 `18 × 18px`，位于抽屉右上角。

返回与关闭语义不同：

- 返回：回到上一级策略列表或组件上下文。
- 关闭：退出整个策略编辑工作区，回到运营页面。

存在未保存内容时，两者都要保留草稿或触发丢弃确认。

### 5.2 策略页签与操作行

第二行位于标题下方 `10px`，高度 `44px`：

- 左侧策略页签与工具区宽 `979px`。
- 右侧提交操作区宽 `210px`。
- 两区间隔约 `22px`。

策略页签：

- 单个页签高度 `44px`，常规宽约 `91px`，间距 `8px`。
- 活动页签使用品牌蓝文字，示例 `#1577FF`。
- 非活动页签使用灰色文字，示例 `#9CA3AF`。
- 每个策略页签右侧有 `16 × 16px` 的关闭图标。
- 页签文字字号约 `18px`。
- 页签应显示策略名称；无名称的新草稿可临时使用“新策略 1”等序号，不硬编码设计稿中的“策略 1”。

页签是独立策略草稿，不是筛选标签或普通 Chip。切换页签时必须保留各自尚未提交的字段状态。

## 6. 页签溢出与工具按钮

### 6.1 More

当策略页签无法在可用宽度内完整展示时：

- 保留一项 `More` 作为溢出菜单入口。
- `More` 高度与策略页签一致，不把它设计成小型文字链接。
- 下拉项高度 `44px`，宽约 `91px`，与普通页签保持同构。
- 下拉项继续提供关闭图标。
- 当前活动策略在下拉中也要有活动态。
- 选择下拉项后关闭菜单，并更新主表单。
- 下拉策略很多时设置最大高度并内部滚动，不让菜单超出抽屉。

活动策略位于溢出菜单时，可将其提升到可见页签区，或持续在 `More` 中显示活动态；同一产品只使用一种规则。

### 6.2 复制与新增

`More` 之后依次是：

- 复制当前策略：`44 × 44px` 图标按钮。
- 新建策略：`44 × 44px` 加号按钮。

两个操作必须保持在溢出菜单之外，避免高频操作被隐藏，并提供 tooltip。

复制规则：

- 复制活动策略的人群、时机、内容和描述。
- 创建新的草稿 ID，不沿用原策略 ID。
- 策略名称需标记为副本或要求用户重新命名。
- 复制后自动切换到新草稿。

新增规则：

- 创建空白策略草稿并自动激活。
- `Where` 仍锁定为当前组件。
- 不覆盖或清空其他页签中的未保存内容。

## 7. 提交操作

顶部右侧操作区水平排列，间距 `16px`：

| 操作 | 尺寸 | 层级 |
| --- | --- | --- |
| 提交 | `74 × 42px` | 次按钮，白底蓝色描边/文字 |
| 提交并编组 | `120 × 42px` | 主按钮，品牌蓝底白字 |

默认语义：

- `提交`：验证并保存当前活动策略，不自动加入策略组。
- `提交并编组`：先保存当前活动策略，再进入选择或创建策略组的流程。

设计中一次只展示一个活动策略表单，因此按钮默认作用于当前活动策略。如果产品需要一次提交所有页签，按钮必须显示批量范围或数量，不能沿用同一文案让用户猜测。

提交期间：

- 两个按钮都进入不可重复提交状态。
- 按钮尺寸保持不变。
- 字段错误定位到对应表单项。
- 成功后更新策略 ID、状态和页签文案。
- “提交并编组”保存成功但编组失败时，不回滚已经保存的策略，并允许重试编组。

## 8. 基本信息区

内容主体位于抽屉内 `x = 40px`、`y = 142px`，宽 `1007px`。主体采用纵向 Auto Layout，区块间距 `20px`，左右内边距 `7px`。

名称与描述使用双列：

| 字段 | 宽度 | 规则 |
| --- | --- | --- |
| 名称 | `480px` | 必填，显示红色 `*` |
| 描述 | `480px` | 可选，不显示必填星号 |

- 两列间距 `33px`。
- 标签高度约 `20px`，字号 `16px`。
- 标签与输入框间距 `10px`。
- 输入框高度 `42px`。
- 名称输入显示当前策略名称；描述使用明确占位文案。
- 名称唯一性、长度和非法字符在字段下方反馈，不只使用 toast。

## 9. Who / Where / When / What

基本信息下方依次排列：

1. `人群 (Who)`
2. `组件 (Where)`
3. `时机 (When)`
4. `内容 (What)`

分组标题字号 `16px`，颜色约 `#111827`。每张摘要选择卡尺寸为 `620 × 70px`，使用浅中性蓝底和轻微径向渐变，不拉伸到整个 `1291px` 抽屉宽度。

这种受控宽度是设计师从原型到设计的重要调整：核心表单保持易扫读，右侧留出后续详情或下钻区域。后续制作相似页面时，不要因为抽屉很宽就把摘要卡铺满。

摘要卡结构：

- 左侧约 `50 × 50px` 的业务插图或图标。
- 中间为主标题和一行元数据。
- 主标题字号约 `18px`，品牌蓝 `#1577FF`。
- 元数据字号约 `12px`，颜色约 `#666665`。
- 可编辑卡在右侧使用箭头，点击进入下一级选择器。
- 整卡可点击时保持单一点击区域，不在卡内再套按钮卡。

### 9.1 人群

示例：`All`。

元数据至少说明人群类型和描述。点击进入人群选择；返回后保留其他三类配置。

### 9.2 组件

示例：`Game-Search-Big Win`，并展示组件描述和组件 ID。

从已选组件发起新建策略时，`Where` 是只读上下文：

- 不显示进入箭头。
- 不允许在抽屉内切换到其他组件。
- 需要换组件时先退出策略编辑，回到手机或组件列表重新选择。

如果未来支持跨组件策略，必须建立单独、明确的产品流程，不能悄悄把当前只读卡变为可选。

### 9.3 时机

示例：`即时生效`。

元数据展示生效起止时间或“不限”。点击进入生效规则和时间配置。

### 9.4 内容

示例：`Big Win 游戏标签`。

元数据展示内容类型、数量和关键限制。点击进入与当前组件类型匹配的内容编辑器。

## 10. 滚动与焦点

- 抽屉内容区独立滚动，背景页面不跟随滚动。
- 标题、策略页签和提交操作建议保持在抽屉顶部可见。
- 打开抽屉后，键盘焦点进入活动策略的第一个未完成必填项；已有完整数据时进入名称字段。
- `Esc`、返回键和关闭按钮遵循同一未保存保护规则。
- 关闭后焦点回到触发“新建策略”的按钮。
- `More` 菜单打开后支持方向键、回车和退出键。

## 11. 原型到设计的修改过程

### 原型保留的业务骨架

- 右侧策略配置工作区。
- 返回、标题、名称、描述。
- Who、Where、When、What 四类配置。
- 当前手机页面作为策略上下文。

### 设计师完成的结构升级

| 原型 | UI 设计 | 修改目的 |
| --- | --- | --- |
| 通用标题“新建策略” | `{组件名} 策略` | 明确当前作用对象 |
| 草稿 Badge + 单一复制入口 | 多策略页签、复制、新增 | 支持并行维护多份策略 |
| 页签无溢出方案 | `More` 下拉 | 控制顶部工具条宽度 |
| 只有“提交” | “提交”与“提交并编组” | 区分保存和策略编组流程 |
| 原型左侧灰色蒙层 | 手机保持清晰、抽屉用阴影分层 | 保留实时上下文，减少割裂感 |
| 抽屉从约 `x = 824px` 开始 | 抽屉从 `x = 629px` 开始 | 增加表单宽度，同时恰好露出完整手机 |
| 简单色块图标和大面积表单行 | 业务插图、双列基本信息、620px 摘要卡 | 提高扫读性和视觉一致性 |
| 组件像普通可配置项 | `Where` 固定当前组件 | 防止策略与触发组件脱节 |

设计稿不是对原型做表面美化，而是把单策略表单升级为“保留预览上下文的多策略编辑工作区”。后续遇到同类需求，应先判断是否存在并行草稿、上下文预览和下钻配置，再选择该模式。

## 12. 状态与权限

必须覆盖：

- 初次新建空白策略。
- 编辑已有策略。
- 复制策略后的未保存草稿。
- 多策略页签切换。
- 页签溢出和 `More` 打开态。
- 删除未保存草稿。
- 删除或关闭已有策略的确认态。
- 表单验证错误。
- 提交中、提交成功、提交失败。
- 提交成功但编组失败。
- 人群、时机或内容已失效。
- 当前组件已被删除或无权限。
- 只读权限：隐藏复制、新增和提交，仅允许查看。

## 13. 验收清单

- 顶部全局导航保持可见，抽屉从导航下方开始。
- 左侧完整露出侧栏、手机和当前组件，不移动手机位置。
- 当前组件在手机中使用稳定的品牌蓝高亮。
- 抽屉覆盖 AI 助手 和 AI 输入栏，内部不重复这些元素。
- 标题使用当前组件名，而不是始终写“新建策略”。
- 活动和非活动策略页签有清晰状态，每个页签均可关闭。
- 页签溢出后出现 `More`，复制和新增按钮仍直接可见。
- 复制、新增和切换不会清空其他策略草稿。
- “提交”与“提交并编组”层级和作用范围清楚。
- 名称必填，描述可选，字段错误就近展示。
- Who、When、What 可下钻，Where 在组件入口场景中只读。
- 摘要卡保持 `620px` 基线宽度，不盲目铺满抽屉。
- 返回、关闭、删除页签和切换页签都处理未保存内容。
- 长内容滚动时仍可找到当前策略和提交操作。
